# docx-to-html

把 `.docx`（Office Open XML）文档**离线**转换成独立 HTML，保留表格、矢量形状、填充、细分割线、浮动照片、旋转/翻转以及真实的制表位，**不依赖 AI 或云端**。

纯 Python 3，**转换器本体仅用标准库，零第三方依赖**。

---

## 初衷（为什么做这个工具）

写简历的软件基本都要收费；网上能找到不少好看的简历模板（`.docx` 格式），但用 Word 改内容、调排版特别费劲——字号、间距、分节线、小图标，稍微一动版式就乱，改完还不一定能压进一页。

于是萌生了一个想法：

> **把关心的 docx 模板转成 HTML → 在网页里填内容、调样式 → 再导出成 PDF。**

HTML/CSS 改起来比 Word 直观得多，导出 PDF 用浏览器打印（矢量、不糊）也比各种位图方案清晰。这个仓库就是这条流水线的**第一环：docx → HTML 转换器**，把模板里那些形状、线条、表格、照片原样保住，后面才好在上面做填充和导出。

---

## 特性

| 特性 | 说明 |
| --- | --- |
| 离线转换 | 不联网、不调用 AI，本地一键跑完 |
| 表格还原 | `table-layout:fixed` + 从 `tblGrid` 生成 `<colgroup>`；`gridSpan`→`colspan`；保留行高与单元格边距 |
| 单元格浮动照片 | 锚定在单元格里的图片注入 `<td>`（相对定位），按真实单元格边距补偿参考点，不再错位、不撑乱行高 |
| 形状还原 | 预设/自定义几何形状（含 `rtTriangle`、`line` 等），保留旋转与翻转；VML / DrawingML 双路径 |
| 线条还原 | 保留线宽、线色，以及标题下的细分割线 |
| 段落间距 | Word 用"空段落/默认段后距"撑间隙，HTML 空段会塌缩——转换器显式还原段后距与小节条间隙，不再丢空白 |
| 制表位 | 还原文档里真实的 tab 停靠位置，不再错位 |
| 字体继承 | 读取 Normal/默认样式字号，无可写 `sz` 的 run 继承正文默认，不再忽大忽小 |
| 零依赖 | 转换器本体仅用 Python 标准库，开箱即用 |

---

## 用法

```bash
python docx2html.py input.docx -o output.html
```

参数说明：

- `input.docx`：待转换的 Word 文档
- `-o output.html`：输出 HTML 路径（缺省时输出到同目录）

输出是**单文件独立 HTML**（内联样式、内联图片 base64），直接用浏览器打开即可，适合后续填内容或打印成 PDF。

## 渲染与校准方法论（开发期用，非生产必需）

转换器本体**零依赖、直接转换即可，不需要 PDF，也不需要 AI**。但为了让"转换是否忠实"可被量化验证，仓库附有一套可选的校准闭环（仅开发期使用）：

1. 用**无头 Edge** 把生成的 HTML 渲染成 PNG；
2. 用 **numpy / Pillow** 扫描页面色带（黑色块、灰色小节条、横幅）的像素位置；
3. 用 **PyMuPDF** 抽取 Word/WPS 导出的 PDF 矢量真值（矩形 `get_drawings()`、嵌入图 `get_images()`、文本 `get_text()`）；
4. 逐带/逐图比对，输出偏差（mm）。

> 关键经验（已写进转换器逻辑，不是硬编码猜的）：
> - Word 用**空段落**撑间隙，HTML 空 `<p>` 会塌成 0 高度 → 必须显式还原段后距，不能依赖空段；
> - 单元格浮动图片的参考点要**含单元格边距**，否则横向偏约 1.9mm；
> - 每个段落显式 `snapToGrid=0` 时，`sectPr` 的 `docGrid` 基线网格**不生效**，行距按 Word 单倍行距处理；
> - 小节条（灰色章节标题）靠"带显式精确行高（`w:spacing line=...`）"这一**规则**识别并补 `margin-bottom`，与模板无关。
>
> ⚠️ 校准闭环依赖 Pillow + PyMuPDF + 无头 Edge，**仅用于开发期核对**，不会进入生产转换流程。

## 已知限制

- 段落间距目前通过"默认段后距 + 小节条段后距"两个值控制，是面向**单页中文简历模板族**校准出来的；风格差异极大的模板可能需微调这两个值（已在代码顶部集中为常量，便于调整）。
- 复杂图表、数学公式、艺术字等非常规元素可能未被完全还原——这类元素在"元素覆盖扫描"中会被标记，遇到时按需补充渲染逻辑。
- 校准闭环（measure 脚本）依赖第三方库与无头浏览器，**不属于转换器本体**。
